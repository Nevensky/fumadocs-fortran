# Sources of the HPC registry

The files in this folder are generated by `scripts/registry/*.mjs` from the pinned upstream sources below; do not
edit them by hand. To rebuild them in Docker (the host needs no Node):

```sh
FDF_NODE_IMAGE=node:26-bookworm-slim scripts/dev.sh node scripts/registry/build.mjs
```

`scripts/registry/sources.json` describes the sources, and `scripts/registry/sources.lock.json` pins the SHA-256 of
every download, so a build either reproduces these files or stops at the first source that changed. `--refresh`
accepts changed sources after review; `--frozen` (for CI) also refuses downloads without a pin. Downloads are cached
in `.cache/registry/`, each in a folder of its own, and are only ever parsed.

The registry is used at build time only: pages embed just the entries they reference.

Each file starts with a `legend` that explains its fields, codes and tags, and a `links` section with the URL
rules of its link providers. `read.mjs` expands entries and builds their links.

## Link targets

These sites are linked to; nothing is downloaded from them or copied.

- [Open MPI 5.0.x documentation](https://docs.open-mpi.org/en/v5.0.x/): Default MPI link target.
- [MPICH documentation](https://www.mpich.org/static/docs/): Answers scripts with 403; the link check tolerates it.
- [Intel oneMKL Developer Reference for Fortran](https://www.intel.com/content/www/us/en/docs/onemkl/developer-reference-fortran/): Link target only; Intel's text is never copied. Answers scripts with 403.
- [OpenBLAS documentation](https://www.openmathlib.org/OpenBLAS/docs/): Link target for the OpenBLAS extensions.
- [NVIDIA HPC SDK, Fortran CUDA Interfaces](https://docs.nvidia.com/hpc-sdk/compilers/fortran-cuda-interfaces/index.html): Link target for cuBLAS; NVIDIA's text is never copied.
- [GCC libgomp manual](https://gcc.gnu.org/onlinedocs/libgomp/): Link target for OpenMP and OpenACC routines and environment variables (GFDL; nothing copied).

## Text not copied

No prose is taken from the GFDL manuals (gfortran, libgomp), the OpenMP, OpenACC or MPI specifications, Intel,
NVIDIA or FFTW. From the specifications and manuals the registry keeps names, page numbers and fragment IDs only. Its
OpenMP (kinds included), OpenACC, BLACS, MPI-callback, MPI-type and vendor one-liners are our own; the
summaries of LAPACK, ScaLAPACK, Open MPI and M_intrinsics come from those projects under their permissive
licences (see NOTICE).
