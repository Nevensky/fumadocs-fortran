title: Get started
description: Add the API reference of your Fortran code to a Fumadocs site, and open it on your own machine.
---

Add the reference to a Fumadocs site as Fumadocs' own integrations are added: install the package, generate the
pages of the Fortran in `src/` into the site's content, and give the site the package's MDX options and loader plugin,
its components and its stylesheet. Each module, submodule and program gets a page, with badges for its kind and for
the high-performance computing (HPC) features it uses, argument tables, the code of each procedure of up to 400
lines, and the letter of each entry's kind in the table of contents.

The steps leave maths and graphs out, so that the site needs no other packages.
[Set up your site](/docs/guides/site-setup) adds them.

<Callout title="Pre-release">
  fumadocs-fortran installs from GitHub, and its pages, options and components can change in any 0.x version.
</Callout>

## Before you begin

The steps add the reference to a Fumadocs site that builds its pages with Fumadocs MDX on Next.js, as the sites of
`create-fumadocs-app` do. For a project without one, [Start a new site](/docs/new-site) makes it, in a `docs/` folder,
and comes back here.

The paths assume that the site is in `docs/`, in your project's top folder, beside the Fortran in `src/`, as fpm and
FORD lay it out. For another folder of Fortran, write its name for `src`. For a site in another folder, write its path
for `docs`, and change the `cd ..` of step 2 to go from the site's folder to the top folder.

The site needs Node.js 22.22 or a later 22 release, or 24.11 or later, and npm needs Git to install the package from
GitHub:

```bash
node --version
```

```bash
git --version
```

## 1. Install the package [#install]

Go into the site's folder, and install the package from GitHub:

```bash
cd docs
```

```bash
npm install github:Nevensky/fumadocs-fortran --allow-git=root
```

npm 12 installs from GitHub only with `--allow-git=root`; npm 10 and 11 need no flag. npm 11 may warn that esbuild's
install script is not covered by `allowScripts`, and npm 12 that it blocked it: the steps work either way. Check that
the command is there:

```bash
npx fumadocs-fortran --version
```

It prints the package's version, such as `0.0.0`.

## 2. Generate the reference [#generate]

Keep the command that writes the reference in a `reference` script of the site's `package.json`:

```bash
npm pkg set scripts.reference="cd .. && fumadocs-fortran generate src -o docs/content/docs/api --math code --graphs none"
```

npm runs a script in the site's folder, with the site's `node_modules/.bin` on its `PATH`, so the script runs the copy
installed in step 1. It goes up to the top folder first, so that the pages name your files as `src/…`, as your
repository does. Run it:

```bash
npm run reference
```

It prints the command, then a line such as this one, for the three files of the example the
[Showcase](/docs/showcase) is generated from, but for the time:

```text
7 files (7 changed, 0 removed) from 3 sources in 70 ms
```

`from 0 sources` means that nothing was read: check the folder's name. Sources that need fypp first, such as `.fypp`
files, are not read either; see [Choose what to show](/docs/guides/generate#what-to-show). The run writes into
`docs/content/docs/api/` the pages, the overview `index.mdx`, the sidebar's `meta.json`, and `.fumadocs-fortran.json`,
the list of its files, so that a later run deletes only its own.

`--math code` shows maths as code and `--graphs none` leaves the graphs out, as the site has no plugins for them yet.
The pages show the code as it builds with no preprocessor macros defined, while the Showcase defines `_OPENMP` and
`USE_MPI`; to document another build, see [Choose the build](/docs/guides/generate#choose-the-build). If the line
ends with a number of diagnostics, the lines under it name the file and line of the first 20, such as a missing
include file; the pages are written all the same.

## 3. Set up the content source [#source]

The site's content source, `lib/source.ts`, defines its docs collection and the loader that serves the collection's
pages. Give the collection the package's page schema and MDX options, and the loader its plugin:

```ts title="docs/lib/source.ts"
import { llms, loader } from 'fumadocs-core/source';
import { docsRoute } from './shared';
import { defineDocs } from 'fumadocs-mdx/macro';
import { applyMdxPreset } from 'fumadocs-mdx/config'; // [!code ++]
import { metaSchema, pageSchema } from 'fumadocs-core/source/schema';
import { fortranPageSchema, withFortran } from 'fumadocs-fortran/mdx'; // [!code ++]
import { fortranPlugin } from 'fumadocs-fortran/source'; // [!code ++]

const docs = defineDocs({
  dir: 'content/docs',
  docs: {
    schema: fortranPageSchema(pageSchema), // [!code highlight]
    mdxOptions: applyMdxPreset(withFortran()), // [!code ++]
    postprocess: {
      includeProcessedMarkdown: true,
    },
  },
  meta: {
    schema: metaSchema,
  },
});

// See https://fumadocs.dev/docs/headless/source-api for more info
export const source = loader({
  baseUrl: docsRoute,
  source: docs.toFumadocsSource(),
  plugins: [fortranPlugin()], // [!code highlight]
});

export const docsLlms = llms(source, {
  renderPage: async (page) => `# ${page.data.title} (${page.url})

${await page.data.getText('processed')}`,
  // link to the files under `/llms.mdx`
  renderUrl: (item) => (/^\/.*\.(md|txt)$/.test(item.url) ? `/llms.mdx${item.url}` : item.url),
});
```

The marked lines are the ones to add or change:

- `fortranPageSchema` keeps the `fortran` field of a generated page's front matter, the kind of each of its entries,
  which Fumadocs' page schema drops.
- `withFortran` gives Fumadocs' code blocks the Fortran grammars, which mark OpenMP, OpenACC and other directive lines,
  and gives the search index the text of the reference's components rather than their tags. `applyMdxPreset` keeps
  Fumadocs' own MDX plugins, which a collection's `mdxOptions` would otherwise replace.
- `fortranPlugin` gives each entry of a generated page's table of contents the letter of its kind (`t` for a type,
  `s` a subroutine, `f` a function and so on), and each generated page the letters of its kind in the sidebar (`mod`
  for a module, `prog` for a program and so on), in the place of an icon.

A site with MDX options of its own gives them to `withFortran`, which adds its own to them:
`applyMdxPreset(withFortran({ remarkPlugins: [myPlugin] }))`. A site that defines its collections in
`source.config.ts`, rather than with the macro API of the static template, gives its `defineDocs` the same `schema`
and `mdxOptions`, and its `loader` the plugin. [JavaScript API](/docs/reference/javascript#fumadocs-fortran-mdx) has
their options.

## 4. Register the components [#register]

The pages are drawn with the components of `fumadocs-fortran/react`. Add them to the site's MDX components, after
Fumadocs' own:

```tsx title="docs/components/mdx.tsx"
import defaultMdxComponents from 'fumadocs-ui/mdx';
import type { MDXComponents } from 'mdx/types';
import { fortranComponents } from 'fumadocs-fortran/react'; // [!code ++]

export function getMDXComponents(components?: MDXComponents) {
  return {
    ...defaultMdxComponents,
    ...fortranComponents, // [!code ++]
    ...components,
  } satisfies MDXComponents;
}

export const useMDXComponents = getMDXComponents;

declare global {
  type MDXProvidedComponents = ReturnType<typeof getMDXComponents>;
}
```

## 5. Import the stylesheet [#stylesheet]

The components' look is in `fumadocs-fortran/style.css`, plain CSS on Fumadocs' colours, which follows the site's
light and dark themes. Import it in the site's global CSS, after Fumadocs' own:

```css title="docs/app/global.css"
@import 'tailwindcss';
@import 'fumadocs-ui/css/neutral.css';
@import 'fumadocs-ui/css/preset.css';
@import 'fumadocs-fortran/style.css'; /* [!code ++] */

html {
  scrollbar-gutter: stable;
}

html > body[data-scroll-locked] {
  margin-right: 0px !important;
  --removed-body-scroll-bar-size: 0px !important;
}
```

To change the package's colours, see [Styling](/docs/reference/components#styling).

## 6. Open the reference [#open]

Start the development server:

```bash
npm run dev
```

It prints its address, `http://localhost:3000`, and may warn that `metadataBase` is not set, which
[Publish on GitHub Pages](/docs/guides/github-pages) sets. Open http://localhost:3000/docs/api in your browser:

- the sidebar has an "API reference" folder, with the overview and your pages under a heading for each kind, each
  page with the letters of its kind;
- the overview has a card for each page, with the summary of its doc comment, or the procedures the page holds;
- on a module's page, each procedure has its badges, signature, documentation and argument table: point to a badge
  or an intent to read what it means, and select a row to open it. The table of contents gives each entry its letter;
- under each procedure of up to 400 lines, a block headed "Source code in" and its file opens to its lines, numbered
  as in the file, with their OpenMP and OpenACC directive lines marked.

Stop the server with Ctrl+C.

## 7. Build the site [#build]

Build the site, and serve it as it will be served:

```bash
npm run build
```

```bash
npm start
```

The build takes a few seconds and prints the `metadataBase` warning again. The static template of
[Start a new site](/docs/new-site) writes the site into `docs/out/`, as static files, and its `npm start` serves them
at `http://localhost:3000`. Stop it with Ctrl+C, and go back to the top folder, where the commands of the guides run:

```bash
cd ..
```

## What you have

- The site's `package.json` has a `reference` script, the command that writes the reference. After a change to your
  Fortran, run it again: it rewrites the pages that changed, and deletes the files its last run wrote and this run did
  not. [Generate the reference](/docs/guides/generate) gives its flags.
- `docs/content/docs/api/` belongs to the generator: change the Fortran rather than the pages. Commit the folder, or
  generate it before each build, as [Publish on GitHub Pages](/docs/guides/github-pages) does.
- Steps 3 to 5 changed three files of the site, by their marked lines: `lib/source.ts`, `components/mdx.tsx` and
  `app/global.css`. Nothing outside the site's folder changed.
