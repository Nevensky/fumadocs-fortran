fumadocs-fortran writes the API reference of a Fortran code as MDX pages, which a fumadocs site builds like its
hand-written ones. It reads the sources with its own parser, written in plain JavaScript with no dependencies, and the
doc comments the code already has, in FORD, Doxygen or LAPACK style. It understands HPC code: OpenMP and OpenACC
directives, MPI and coarrays, cpp conditions, and calls into BLAS, LAPACK and ScaLAPACK.

<Callout title="In development">
  The parser is done and checked against public codes. Page generation and this site are the first slice of v0.1,
  and nothing is published to npm yet.
</Callout>

## Showcase

The pages under [Showcase](/docs/showcase/modern) are generated from `examples/modern` in the repository, a small
code written to use every feature: FORD comments in free form, Doxygen comments, a LAPACK-style routine in fixed form,
OpenMP, OpenACC, MPI, coarrays and cpp conditions. `docs/scripts/gen-showcase.mjs` writes them, so change the
Fortran and run it again rather than editing a page.

## What a page holds

Each module, submodule and program gets a page, and each of its types, interfaces, procedures and variables a
section under its own anchor, with:

- badges for its kind and for the HPC features it uses, dashed when a cpp condition decides whether it exists;
- its signature, highlighted as Fortran;
- its documentation, as Markdown with maths, such as $\|x\|_2 = \sqrt{\sum_i x_i^2}$;
- its arguments, result, components or bindings as a table: a row each, with the type, shape, intent and attributes,
  which opens to the documentation in full Markdown, the declaration, the meaning of each attribute and the shape in
  words;
- hover cards on the kind names and derived types in those tables, which link to their definitions, or to the
  standards for mpi_f08's types and omp_lib's kinds, and on the BLAS, LAPACK, ScaLAPACK, MPI, OpenMP and OpenACC
  routines it calls, which link to their documentation; every badge, intent, attribute, shape and type parameter's
  `kind` or `len` says what it means on hover;
- graphs: a type's parents and extensions, a procedure's callers and callees, with library routines in their
  library's colour, and, on a unit's page, what it uses and what uses it, with every unit and the HPC libraries it
  uses on the overview;
- its own code, in a block that opens, numbered as in its file and linked to its lines on GitHub (past 400 lines,
  the link alone).

The page's table of contents marks each entry with a letter for its kind: `t` a type, `s` a subroutine, `f` a
function and so on.
